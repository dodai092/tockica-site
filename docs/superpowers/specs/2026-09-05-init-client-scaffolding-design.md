# init-client scaffolding, font-mode prompt, and string-match guard (Gap C)

Date: 2026-09-05
Status: design approved, spec for review. Source: `docs/superpowers/specs/2026-09-05-post-setup-rewrite-gaps.md` Gap C.

## Problem

After `npm run init-client`, SETUP.md step B1c is a ten-plus item manual checklist with
nothing tracking which items are done, and B1b tells the operator to copy three doc
templates into place by hand. Half-done items surface only in the B4 verification pass,
at the start of the build where a miss costs the most. Separately, `init-client`'s
self-identity rewrites string-match doc text verbatim and broke once already (commit
`3a08f2d`) when SETUP.md was reworded; `replaceInFile` only warns on a miss, so the
regression was silent until a whole-branch review caught it.

## Scope

Changes to `scripts/init-client.mjs`, one SETUP.md edit, one CONTEXT.md edit, one new ADR.
No other core files. No test framework added.

1. Font-mode prompt (default system).
2. Scaffold `docs/intake.md` and `docs/handoff.md` from their `-template` sources.
3. Emit `docs/reinit-checklist.md`.
4. `REPLACEMENTS` table + `node scripts/init-client.mjs --check` guard, wired into `npm run check`.
5. `CONTEXT.md` "Related docs" SETUP.md pointer fix (pre-existing mismatch, folded in).
6. ADR 0003.

Not in scope: the discovery-to-plan gate (Gap B, done at commit `428c2de`); the legal
"client needs a new policy" procedure (still open, tracked in the gaps doc); backfilling
`vinalia-site` schema.

## 1. Font-mode prompt

New prompt in the answer-gathering block, after the primary-colour prompt:

```
Custom web font or system stack? (custom/system) [system]
```

Answer handling (blank or unrecognised -> `system`, consistent with the other prompts and
with piped/non-interactive runs):

- **`system`**:
  - `src/brand.ts`: replace the three `fonts.*` values with system stacks.
    - `sans`: `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif`
    - `serif`: `Georgia, "Times New Roman", serif`
    - `heading`: same string as `sans`
  - `astro.config.ts`: replace the whole `fonts: [ ... ],` block with `fonts: [],`.
  - `src/fonts.ts`: replace `export const preloadFonts: string[] = ['--font-inter'];`
    with `export const preloadFonts: string[] = [];`.
  - `docs/reinit-checklist.md`: the font row is written pre-ticked with a short
    "system stack wired by init-client" note.
- **`custom`**: no file changes (today's exact behaviour). The checklist font row stays
  unticked with the custom-typeface instruction.

The `astro.config.ts` and `src/brand.ts` font edits are conditional (only on `system`
runs) but their `from` literals are still verified by `--check` on every run (see section 4).

Rationale for default `system`: it matches the script's `[default]` enter-key convention,
keeps piped runs working, and the enter-key path then ships no fetched web font and no
typeface the client did not ask for. System mode is also the one needing the most wiring,
so automating it removes the most manual error surface. `custom` as default would change
nothing from today and add a prompt for no gain. Weak corroboration: Vinalia (the one real
build) was system/Arial.

## 2. Scaffold working docs

In the file-editing block, after the legal pages:

- Copy `docs/intake-template.md` -> `docs/intake.md`.
- Copy `docs/handoff-template.md` -> `docs/handoff.md`.
- Do **not** copy `docs/go-live.md`: it is a fixed launch runbook, not a per-client
  fill-in, and has no `-template` suffix. Left in place as-is.
- The `-template` originals stay in the client repo as reference (not stripped).
- If `docs/intake.md` or `docs/handoff.md` already exists, skip that copy and warn
  (same defensive shape as `replaceInFile`'s not-found warning). An operator re-running
  init should not clobber a filled-in intake.

End-of-run output: the "Docs: work through docs/intake-template.md, docs/go-live.md,
docs/handoff-template.md" line becomes:

```
  - Docs: docs/intake.md and docs/handoff.md scaffolded; fill them in.
    docs/go-live.md is the launch runbook (no per-client edits).
```

## 3. `docs/reinit-checklist.md`

`init-client` writes this file from a template literal in the script. Content is B1c's
brand/asset items plus B1d's analytics items as GitHub task-list lines, with client name
and jurisdiction interpolated where useful. Structure:

```markdown
# <name> reinit checklist

Generated by `npm run init-client`. Tick items as you complete them. The B4 verification
pass reads this file. Canonical explained version: SETUP.md step B1c / B1d.

## Brand and assets

- [ ] src/brand.ts: secondary / accent / text / background colours (design phase)
- [<font row, state per prompt>] Fonts
- [ ] src/navigation.ts: real header/footer nav
- [ ] Logos / assets: public/ and src/assets/images/, favicons (favicon.ico multi-size), default.png OG
- [ ] src/brand.ts logo.image / logo.alt (uncomment the import)
- [ ] public/robots.txt, public/_headers checked
- [ ] Blog: apps.blog.isEnabled left false unless wanted
- [ ] src/schema.ts: address / phone / hours if a local business
- [ ] ui.theme in config.yaml if a fixed light/dark mode

## Analytics (SETUP.md B1d)

- [ ] GA4 Measurement ID in src/config.yaml analytics.vendors.googleAnalytics.id
- [ ] EU/GDPR: requireConsent: true, adapt src/components/client/CookieConsent.astro, render from GlobalEmbeds.astro
```

Font row:

- `system`: `- [x] Fonts: system stack wired by init-client (astro.config.ts fonts: [], src/fonts.ts empty, brand.fonts.* system stacks)`
- `custom`: `- [ ] Fonts: add the family to astro.config.ts fonts, list its cssVariable in src/fonts.ts, point brand.fonts.* at it`

The file is committed by the operator with the rest of the init changes. If it already
exists, warn and skip (do not overwrite a checklist with progress ticked).

SETUP.md B1c gets one added sentence at the top of the checklist:

> `init-client` emits this list as `docs/reinit-checklist.md`; tick items there as you go.
> This section stays the explained canonical version.

B1c and the generated file are kept in sync by hand; a future divergence is low-cost and
visible. Not worth generating B1c from a shared source.

## 4. `REPLACEMENTS` table and `--check` guard

### Restructure

Every `replaceInFile(path, pairs)` call site today holds its `from`/`to` literals inline,
several as multi-line template strings. Collect them into one array at the top of the
script:

```js
// Every verbatim doc/config match init-client makes. `when` gates application;
// `--check` verifies every `from` is still present regardless of `when`.
const REPLACEMENTS = [
  { file: 'package.json', from: '"name": "dodai-astrowind"', to: () => `"name": "${slugify(name)}"` },
  // ... one entry per pair, `to` a function so it can close over answers
  {
    file: 'astro.config.ts',
    from: '<the fonts: [...] block>',
    to: () => 'fonts: [],',
    when: () => fontMode === 'system',
  },
  // ...
];
```

The apply loop groups entries by `file`, skips any whose `when` returns false, and runs
the existing `replaceInFile` split/join. `to` becomes a function (or a string) so entries
can be declared before answers are gathered; apply resolves them.

Legal-page pairs (`{{LAST_UPDATED}}` etc.) and the `dropExamples` / file-strip logic stay
as they are: they are not verbatim doc-prose matches and are not the failure this guards.

### `--check`

`node scripts/init-client.mjs --check`:

1. If no `.template-repo` marker in cwd, print "not a template repo, nothing to check"
   and exit 0. (In a client repo the strings are already replaced; the check is
   meaningless there.)
2. For each `REPLACEMENTS` entry, read `file` once (cache) and assert `text.includes(from)`.
3. On any miss, print each offender as `file: "<first 60 chars of from>..." not found`
   and exit 1. Otherwise print "N/N init-client matches present" and exit 0.
4. Touch no files.

Argument parsing: a single `if (process.argv.includes('--check')) { await runCheck(); process.exit(...) }`
near the top, before the prompter is created.

### Wiring

Add to `package.json`:

```
"check:init": "node scripts/init-client.mjs --check",
```

and append `&& npm run check:init` to the `check` script. In a client repo it exits 0 at
step 1. In the template repo, pre-commit (`npm run check` via the hook chain) and CI both
run it, so a doc reword that breaks a match fails the commit that made it.

## 5. CONTEXT.md pointer fix

`CONTEXT.md` line 46, in "Related docs":

```
- [SETUP.md](./SETUP.md), the per-client build workflow (Discovery, Build, Launch)
```

`init-client`'s CLAUDE.md rewrite drops the SETUP.md line from its ordered read-list and
its AGENTS.md rewrite rewrites the SETUP.md reference; CONTEXT.md's is untouched, so a
client repo ends up with CONTEXT.md pointing at a "workflow" that the renamed SETUP.md no
longer is. Add a `REPLACEMENTS` entry:

- from: `- [SETUP.md](./SETUP.md), the per-client build workflow (Discovery, Build, Launch)`
- to: `- [SETUP.md](./SETUP.md), the build reference kept from the template`

Applied unconditionally, same as the other self-identity rewrites.

## 6. ADR 0003

`docs/adr/0003-init-client-scaffolding-and-string-guard.md`. Status Accepted (implemented
in the same change). Records:

- Default-`system` font mode and why (section 1 rationale). References ADR 0002 item 1,
  which documented the system-font path; this makes it the enter-key default.
- `docs/go-live.md` deliberately not copied (fixed runbook).
- `REPLACEMENTS` table + `--check` as the guard against silent match drift, wired into
  `npm run check`.
- `docs/reinit-checklist.md` as the tracked B4 input; B1c stays canonical.
- Consequence: `init-client.mjs` is now the single source of truth for its own verbatim
  matches, and any doc reword near a matched string fails `npm run check` until the
  literal is updated.

## 7. Verification

No unit-test framework in the repo; not adding one. Verification is a scratchpad dry run
(documented in the plan, run by the implementer):

1. Copy the template working tree to a temp dir outside the repo.
2. `npm run init-client` with piped answers, font mode `system`. Assert:
   - `docs/intake.md`, `docs/handoff.md`, `docs/reinit-checklist.md` exist.
   - `astro.config.ts` has `fonts: [],`; `src/fonts.ts` `preloadFonts` is `[]`;
     `src/brand.ts` `fonts.*` are the system stacks.
   - checklist font row is the pre-ticked `system` line.
   - `npm run check` and `npm run build` pass.
3. Repeat with font mode `custom`. Assert `astro.config.ts` / `fonts.ts` / `brand.ts`
   fonts are unchanged from the template, checklist font row is the unticked `custom` line.
4. In the real template repo: `npm run check:init` exits 0. Then hand-edit one word inside
   a matched doc string, re-run, assert exit 1 naming that file, revert.

## Success criteria

- A fresh fork after `init-client` has `docs/reinit-checklist.md`, `docs/intake.md`,
  `docs/handoff.md` in place; the font-mode prompt ran and wired the chosen mode end to end.
- `node scripts/init-client.mjs --check` guards every `REPLACEMENTS` `from` literal and is
  in the `check` chain.
- `npm run check` and `npm run build` pass in the template repo and in a freshly
  init-ed fork (both font modes).
- ADR 0003 committed.
