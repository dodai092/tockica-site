1. Hug the content Score: 8/10

The panel is as wide as its longest label, with a 200px floor. The right-aligned list stays where it is now.

  • Pro: one property changes (width: max-content). Keeps the dropdown, its fold and its motion as they are.
  • Pro: no leftover strip, the card sits close to the labels.
  • Con: the "Book a class" button gets narrower too, so it reads smaller than the list.

2. Fixed narrow card (240px) Score: 6/10

Same right-aligned card, width set to 240px.

  • Pro: the simplest change, and the look stays the same.
  • Con: a fixed number ignores the screen. At a larger text size "Sculpt Room" and the button crowd each other.
  • Con: the labels still sit at the right edge, so the card looks like a sliver of the screen.

3. Side drawer, 280px, full height Score: 5/10

The menu slides in from the right edge under the bar and fills the height of the screen.

  • Pro: a clear surface that reads as a separate menu, and a common mobile pattern.
  • Con: a new motion. Slide on the drawer curve is not in the animation rules yet, so it needs a rule and a test.
  • Con: needs its own dim, focus handling and close path. More code than the problem needs.

4. Full-width sheet, left-aligned Score: 4/10

Drops the floating card. The sheet runs edge to edge under the bar, with labels on the left.

  • Pro: no width to get wrong, and left-aligned labels read well at phone size.
  • Con: it covers the full width, which is the thing the complaint is about.
  • Con: it drops the glass card the header is built on, so the menu no longer matches the bar.
